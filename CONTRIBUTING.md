# Contributing to DevKit

Thank you for helping make this resource collection more useful. You do not need to write application code; clear documentation edits, verified links, and careful corrections are valuable contributions.

## What to contribute

- Suggest a useful developer tool or learning resource.
- Add an official documentation link.
- Correct a broken link, outdated pricing note, or factual error.
- Improve clarity, accessibility, spelling, or Markdown formatting.

## Before you contribute

1. Search the repository to avoid duplicate entries.
2. Prefer the resource's official website and documentation.
3. Check the link and current pricing on the provider's own site.
4. Explain the resource's purpose, audience, and meaningful limitations.
5. Do not include confidential information, credentials, or affiliate links.

## Add a resource

Use the [resource suggestion template](.github/ISSUE_TEMPLATE/resource-suggestion.md) for an idea. For a pull request, place it in the most relevant category and follow the format already used there. For tool entries, include its website, category, pricing, best use, key features, advantages, limitations, and official documentation where available.

Pricing labels should distinguish **Free**, **Freemium**, and **Paid**. Use **Freemium** when core access is free but paid plans or meaningful limits apply. If current terms cannot be confirmed, say **Pricing: Verify with provider** instead of guessing.

## Report a problem

Use the [broken link template](.github/ISSUE_TEMPLATE/broken-link.md) for unavailable or redirected links. For security concerns, follow [SECURITY.md](SECURITY.md) rather than posting sensitive details publicly.

## Pull request checklist

- [ ] The change is in the correct category and is not a duplicate.
- [ ] Official links work and point to the relevant page.
- [ ] Pricing and limitations are accurate or explicitly marked for verification.
- [ ] The resource's usefulness is clear to its intended audience.
- [ ] Markdown formatting is consistent and internal links are valid.
- [ ] No secrets, personal data, spam, or misleading promotions are included.

Keep changes focused and descriptions factual. Maintainers may ask for clarification or decline entries that do not meet these standards.
